## 先说清楚，我们在聊什么

这两年 agent 这个词被用得有点滥。聊不到三句，模型、框架、agent、Harness 就搅成一锅。开讲之前，先把三样东西掰开。

**模型，就是一个无状态的推理函数。** token 进去，token 出来，下一个字选谁，由概率决定；权重不会因为聊过什么而改变，这次喂进去的东西一样，它面对的概率分布就一样，上一轮什么也没留下。它没有文件，没有进程。你在产品里看到的"它记得我"——跨会话记忆、历史对话——没有一样真存在模型里，都是外面的壳存下来，下次调用前重新拼进输入喂回去的，这个第 4 篇细讲。单拎出来看，它不是什么 agent，只是一个零件——而且是个偶尔会胡说八道、还说得特别笃定的零件。

**Harness，是包在模型外面的那一整套工程。** 下一步做什么由谁来定，上下文里装什么、不装什么，工具怎么调，命令在哪跑，危险操作谁来批，历史怎么存、断了怎么续，界面长什么样——全在这层壳里。模型之所以看起来像个"agent"，靠的全是这层壳：它的每一个行为，都是壳安排出来的。这个系列聊的东西，几乎全在这层壳上。

**环境，是 agent 动手的那个世界。** 文件系统、shell、git 仓库、浏览器、网络、别的服务，以及人。

这三样东西之间有三条边。后面每一篇，其实都在摸其中某一条：

- **推理边界**：Harness 到模型，一次 token 往返。这是整个系统里唯一的概率接缝——回来的会是什么，你不能假设。
- **副作用边界**：Harness 到环境，工具真正动手的地方。进程外面的世界，只在这条边上被改变。
- **人本边界**：人和 Harness 之间。下指令、卡审批、随时打断——授权可以放出去，权力不能全交。

不讲的也挑明：模型训练、权重、推理内核、GPU 调度，那是模型团队的世界，这边不碰；也不会有什么提示词偏方大全。这个系列只回答一件事：**把一个模型变成一个能真正干活的系统，需要哪些工程。**

## 和传统软件工程，差在哪

我很认一句话：Harness 里九成是传统软件工程，剩下那一成不是"更难的工程"，而是系统里负责"下一步做什么"的那个控制部件，从确定性程序变成概率模型之后，引发的一连串连锁反应。

空说没感觉，把一个工业级的 coding agent 摊开看就明白了。下图是照着 OpenAI 开源的 codex 的模块结构整理的——Rust 写的，上百个 crate，是目前能看到的最完整的样本之一。

<figcaption>图 2 · 工业级 Harness 的模块分类图（据 codex 的 crate 结构整理，灰橙红青四根立柱按与模型的关系分类）</figcaption>
</figure>

四根立柱：

- **灰的，九成的底盘。** 界面、网络代理、密钥、文件和 git、安装包。没有 LLM 这些模块照样存在，该怎么写怎么写，用的是你干了多年的老手艺。
- **红的，才是新长出来的那一成。** turn 循环、上下文工程、指令层级、工具结果回灌、决策回放。传统软件里你找不到对应物。
- **青的，老手艺换了个新岗位。** 模型网关、协议适配、事件存储，还有一副内核撑着 CLI、IDE、云端好几副面孔。都是围着 LLM 建的，但真正难的是限流重试、故障切换、版本兼容——跟概率没什么关系。
- **橙的，是污染带。** 位置在传统地盘里，干的也是老行当，但契约被概率边界改写了——这根柱子最咬人，单独说。

橙柱里这几个模块，以前都是再熟悉不过的东西：

- 沙箱以前防的是外部攻击者，现在要防的是你自己的 agent——它不是使坏，它是真心觉得这一步 `rm -rf` 合理；
- 进程执行器以前接收人敲的命令，现在接收模型生成的字符串，命令注入面、进程挂死的语义，全变了；
- 配置以前是 YAML 这种形式语言，现在 AGENTS.md 是自然语言，它出错的方式从此不一样；
- 日志和指标以前帮你定位"哪里报错了"，现在你得靠它们回放"它当时为什么这么想"。

**模块是老模块，契约是新契约。** 这就是图上说的"污染带"。

根因一句话：

> 传统系统的控制流是可以枚举的；agent 把"下一步做什么"这个控制权，交给了一个概率函数。

于是设计目标整个变了：以前追求"接口是对的"，现在要保证的是"**就算模型理解错了，系统照样安全、能恢复、可观测**"。后面每一个红色、橙色模块为什么长那样，都能追到这句话。

## 这个系列打算怎么写

主线是**一次 turn 的生命周期**：你敲下回车，到任务结束，中间每一环都拆开看。研究对象主要是两个开源仓库：codex（Rust，工业级的完整样本）和 opencode（TypeScript，另一种风格的对照）。每篇固定路子：一个核心问题、两个实现对照、关键代码切片、一张图。

计划中的篇目：

1. 一个 turn 的一生——回车之后到底发生了什么
2. 内核循环：规划、反思，和一个可能停不下来的状态机
3. 模型边界：协议、限流、故障切换与成本
4. 上下文与记忆：寄存器、内存和磁盘
5. 工具与执行：模型怎么真正动手
6. 沙箱与信任边界：防的是自己人
7. 指令层级：用自然语言编程
8. 扩展生态：MCP、hooks、plugin 各是什么
9. 一副内核多副面孔，以及多智能体
10. 概率系统怎么测；收口：造 Harness 的几条原则

顺序和篇目大概率会边写边调。

写这个系列对我自己也是个交代：干了十几年后端和平台，agent 这摊东西里，哪些是吃饭的老本事换了件衣服，哪些是真没见过的新问题，把它拆明白，比追着新名词跑要紧得多。
